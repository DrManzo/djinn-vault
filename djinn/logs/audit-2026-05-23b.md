### 5. Critical Bug Fixed — opencode `--` Argument Separator

**Bug:** `opencode run -f file.md "message"` treats the message as a file path when `-f` is used.

**Symptom:** All comms-processor and djinn-morning opencode invocations failing instantly with "File not found: [message content]". This caused every `|| RESPONSE="[ERROR]..."` fallback to fire.

**Fix:** Add `--` before the message argument in both scripts:
```bash
# Before (broken):
opencode run -f soul.md -f agents.md "$PROMPT"

# After (fixed):
opencode run -f soul.md -f agents.md -- "$PROMPT"
```

**Files fixed:** `~/.local/bin/comms-processor`, `~/.local/bin/djinn-morning`
**Pushed to Typhon:** yes, via `scp`

---

### 6. Headless Tool Permissions Fix

**Bug:** In `opencode run` (non-interactive), tool permission requests are auto-rejected. The model tries to write files or run commands, gets a `permission requested: external_directory; auto-rejecting` error, produces empty output.

**Fix:** Add `--dangerously-skip-permissions` to headless invocations.

**Note:** This is intentional for automation scripts running as the user. OpenClaw's exec-approvals system governs interactive tool use separately.

## Known Limitations

**qwen2.5:7b headless tool execution:** The model responds to COMMS tasks as conversation, not as a shell agent. It generates descriptive text ("I would write X to Y") instead of invoking the write_file/run_command tools opencode provides. This is a model behavior issue, not a configuration issue. 

**Workaround:** Route execution tasks to Claude (interactive) or use direct SSH. Use comms-processor for: summaries, status reports, content generation, note writing.
