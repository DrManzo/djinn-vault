# Session Report — Calliope Error 3343 + nozzle_mcu Diagnostic Deep Dive

**Date:** 2026-06-02  
**Agent:** Claude  
**Session type:** Debug / Research  
**Trigger:** Proxy Stand pair print failing repeatedly mid-print on 2-week-old Ender-3 V3 Plus (Calliope). New error code 3343 appeared during cube calibration print.

---

## Summary

Multiple Proxy Stand prints failed with key561 ("Lost communication with MCU 'nozzle_mcu'"). A code-level tracer (`djinn-print-tracer`) was built and deployed, pinpointing the failure to Y≈120–140 on the print bed — consistent across all attempts, confirming position-dependent cable stress. Concurrently, error 3343 appeared on the touchscreen, which research confirms is undocumented in Creality's official error list and most likely originates from the strain gauge subsystem or represents two error codes firing simultaneously. The cumulative picture: Calliope has two overlapping hardware/calibration issues that are compounding each other.

---

## What Was Built or Changed

- **`~/.local/bin/djinn-print-tracer`** — new real-time diagnostic tool. Polls Moonraker every 5s during active prints. Captures per-sample: nozzle_mcu retransmit_seq, bytes_invalid, rto, send_seq, XY position, hotend/bed temps. Sends Telegram alert when retx% > 50 or bytes_invalid > 20. Writes `~/Obsidian/djinn/printer/active/TRACE-<timestamp>.md`.
- **`~/Obsidian/djinn/printer/error_log.md`** — updated with key561 history, trace methodology, and quick-reference row for key561.

- Individual STLs re-sliced as solo jobs: `Proxy_Stand_TF_solo.gcode`, `Proxy_Stand_TTHQ_solo.gcode` — both uploaded to Calliope.

## Technical Decisions

**Solo jobs over combined plate — Why:** Combined plate (`combined_jobs_2_3.gcode`, ~104min) exceeded cable tolerance window. Single stand (~52min) was hypothesis for surviving duration. Ruled out — failure occurs at first-layer Y position regardless of print duration.

**djinn-print-tracer over enhancing existing monitor — Why:** Existing `djinn-print-monitor-v2` only detects failures, doesn't capture causal state. A dedicated high-frequency tracer was needed to correlate nozzle_mcu stats with XY position in real time.

**Firmware restart between attempts — Why:** Clears Klipper MCU error cache and re-establishes serial connection to nozzle_mcu cleanly. Without it, the previous session's error state bleeds into the new print.

### Failure signature (key561)

| Attempt | Duration | Filament | Failure X | Failure Y | Z |
|---------|----------|----------|-----------|-----------|---|
| Job 000031 | 369s | 741mm | — | — | — |
| Job 000032 | 522s | 1109mm | — | — | — |
| Job 000033 | 1233s | — | — | — | — |
| TF solo #1 | 363s | 818mm | 123.82 | 136.11 | 0.70 |
| TF solo #2 | 63s | 133mm | 162.72 | 124.43 | 0.31 |

**Y=120–140 is the confirmed kill zone.** The connection transitions from 0.1% retransmit to 100% retransmit in a single 5-second polling interval. This is instantaneous — not gradual degradation. Cable binding, not EMI accumulation.

**bytes_invalid progression across attempts:** 0 → 5390 → 7290 → 15118 → 20058. The cable is being physically damaged by repeated stress cycles.

### Error 3343 — Research findings

Error 3343 **does not appear in Creality's official V3 Plus error code documentation.** Official codes: 111, 2000, 2022, 2243, 2403, 2527, 2529, 2564. Anything outside this range is either a Klipper-internal runtime exception or a display artifact from two codes firing simultaneously.

**Most probable cause: Strain gauge subsystem.** The V3 Plus uses 4 strain gauges under the bed plate (no CR-Touch). The 25xx/3xxx error range during self-test is almost exclusively generated by this system.

**Second probable cause: Firmware version mismatch.** Creality Print V6.0.x + firmware 1.2.3.23 caused widespread calibration failures across the V3 Plus fleet (late 2024 reports). Community fix: roll back to Creality Print V5.1.x + firmware 1.2.3.21.

**Djinn-specific risk identified:** G-code filenames containing underscores, dashes, or apostrophes (e.g., `Proxy_Stand_TF_solo.gcode`) trigger erratic behavior on the V3 Plus — including mid-print errors, air probing, and failed self-tests. **All Djinn gcode output files should use clean alphanumeric names with hyphens only**, no underscores.

## Repair Procedures — Ordered by Priority

### 1. Strain gauge re-seat (error 3343 fix) — ~15 min
- Power off Calliope
- Remove bed plate
- Disconnect and re-seat all 4 strain gauge sensor connectors
- Re-tighten 4 hex mounting screws: finger-tight + quarter turn only (over-tightening deforms the sensor)
- Re-run self-test on a solid, isolated, vibration-free surface

### 2. nozzle_mcu cable routing fix (key561 fix) — ~10 min
- Follow nozzle_mcu cable from hotend housing along X-gantry
- Find entry point into drag chain
- Add a free loop (~3–4cm) at the toolhead end before the cable enters the chain
- Unclip any cable ties that are holding it taut along the gantry
- Test: manually move bed to Y=120 and watch nozzle_mcu retransmit_seq — should stay ≤5

### 3. Firmware audit — ~5 min
- Check current firmware version on touchscreen: Settings → About
- If on 1.2.3.23 or newer: roll back to 1.2.3.21 via SD card flash
- If on Creality Print V6.x: roll back to V5.1.x

### 4. Gcode filename sanitization — immediate
- Rename output files from Djinn's slicing pipeline to use hyphens, not underscores
- `Proxy_Stand_TF_solo.gcode` → `ProxyStandTF.gcode` or `proxy-stand-tf.gcode`
- Update djinn-model-slice or the slicing pipeline to enforce clean names going forward

### 5. Stable surface check
- If Calliope is on a workbench that vibrates during operation, the strain gauge self-test will fail
- Isolate from desk vibration during self-test and first-layer calibration

### 6. Factory reset (last resort)
- Only if firmware rollback + re-seat don't resolve error 3343
- Settings → Restore Factory Settings → re-run full setup from scratch

## Known Issues / Caveats

- nozzle_mcu cable has been stress-cycled multiple times — `bytes_invalid` climbed from 0 to 20k+. Even after routing fix, monitor closely for continued degradation. Cable replacement may still be needed.
- Error 3343 is undocumented — root cause not 100% confirmed. Strain gauge re-seat is highest-probability fix, not guaranteed.
- Gcode filename issue (underscores) may have been contributing to some failures throughout this session. Cannot confirm retroactively.
- Tracer PID management: killing tracer between print attempts requires `pkill -f djinn-print-tracer`. Should be wired into a systemd unit for cleaner lifecycle management.
