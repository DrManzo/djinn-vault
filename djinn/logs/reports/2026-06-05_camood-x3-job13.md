# Session Report — Camood TTHQ x3 / job13 gcode

**Date:** 2026-06-05
**Agent:** Claude

---

## Summary

Goal: 3× Camood TTHQ on one plate with supports stopping at Z=50mm. Initial approach (3MF with `SupportBlocker` volume type) failed — PS printed the blocker box as solid geometry. Diagnosed root cause: `SupportBlocker` volumes work correctly in single-instance 3MF but PrusaSlicer breaks when 3 build items share the same object ID. Solved via `djinn-gcode-support-cap` post-processor that strips support extrusion moves above a threshold Z, applied after `djinn-gcode-safety`. Final job13 gcode passes all gates.

---

## What Was Built or Changed

- **`~/.local/bin/djinn-gcode-support-cap`** — NEW: strips support material extrusion above Z_MAX mm. Preserves travel moves, only removes E component from G1 support moves (or skips pure retract-in-support lines). Usage: `djinn-gcode-support-cap INPUT OUTPUT Z_MM`
- **`~/.local/share/forge/gcode/Camood_TTHQ_x3_job13.gcode`** — final gcode: 3× Camood, 372g, 22h 29m, support stopped at 50mm, speed cap + pause safety injections

---

## Technical Decisions

**gcode post-processing instead of 3MF blocker volume — Why:** PrusaSlicer's `SupportBlocker` volume type works correctly in single-instance 3MF (tested: 0 support extrusion above 50mm). But with multiple build items pointing to the same object ID, PS treats the blocker mesh as printable geometry (753k extrusion moves above 107mm, 583g vs expected 372g). The gcode post-processor approach is format-agnostic and guaranteed to work regardless of PS's multi-instance behavior. 

**Stripping E only, not full G1 lines — Why:** Deleting support G1 lines entirely would leave the toolhead in an undefined position after a support section ends. Removing only the E component turns extrusion moves into travel moves, preserving path continuity.

**Support cap Z=50mm — Why:** Camood geometry requires supports only in the lower body region (ring collar and cap geometry). Above 50mm is the flat panel area; support there would require cleanup after print and adds print time. This matches the Z=50mm cap from job9.

## Bugs

### Bug: PrusaSlicer ignores SupportBlocker volume type for multi-instance 3MF

**Root cause:** When multiple `<item>` build elements reference the same object ID in a 3MF, PrusaSlicer does not correctly apply the `SupportBlocker` volume type from the config. The modifier volume is treated as printable geometry, adding ~210mm of phantom print above the model (Z=107mm to 127mm).

**Workaround:** `djinn-gcode-support-cap` post-processor strips support extrusion above the cap Z after slicing.

**Single-instance confirmed working:** `camood_blocked.3mf` (single `<item objectid="1"/>`) correctly produces 0 support moves above Z=50mm.
