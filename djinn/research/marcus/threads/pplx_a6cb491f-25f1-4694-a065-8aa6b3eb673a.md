Okay Javier, I found exactly what you're looking for. The Telegram sync errors hitting Marcus are a known OpenClaw issue — specifically an EmbeddedAttemptSessionTakeoverError, which is a session race condition that fires when the active session's totalTokens approaches the model's context window limit.

Here's the full diagnosis and fix from your TROUBLESHOOT.md:

What's Happening

Marcus (the OpenClaw gateway, running mistral:7b) is hitting a stuck or full session via the Telegram channel (@DjinnOCBot). The sync error is triggered when either the session token count nears the context window, or two requests collide on the same session slot — classic race condition in OpenClaw's polling loop.

Step-by-Step Fix

1. Check if OpenClaw is running:

bash
systemctl --user status openclaw

2. Check the logs for the exact error:

bash
journalctl --user -u openclaw -n 100

Look for EmbeddedAttemptSessionTakeoverError.

3. Inspect session state and token counts:

bash
python3 - <<'EOF'
import json, pathlib
f = pathlib.Path.home() / '.openclaw/agents/main/sessions/sessions.json'
d = json.loads(f.read_text())
for peer, s in d.items():
    print(peer, s.get('totalTokens'), s.get('status'))
EOF

4. If totalTokens is near the context window — reset that session:

bash
python3 -c "
import json, uuid, pathlib
f = pathlib.Path.home() / '.openclaw/agents/main/sessions/sessions.json'
d = json.loads(f.read_text())
peer = 'PEER_KEY_HERE'  # replace with the key from step 3
d[peer] = {'id': str(uuid.uuid4()), 'totalTokens': 0, 'status': 'idle', 'compactionCount': 0}
f.write_text(json.dumps(d, indent=2))
print('reset done')
"

5. Restart the gateway:

bash
systemctl --user restart openclaw-gateway.service
