# ubuntu

Yes — the clean way is to run Ollama as your local model server and point OpenClaw at it during onboarding or in its config, then let OpenClaw handle the agent, channels, and workspace locally. OpenClaw’s recommended setup is openclaw onboard, and Ollama exposes a local API at http://localhost:11434 with no auth required for local access.

What to install

You need Node 24 or Node 22.16+ for OpenClaw, and OpenClaw supports macOS, Linux, and Windows, with WSL2 described as the more stable Windows path. OpenClaw can be installed by script or by npm, and the recommended CLI flow is to run onboarding with daemon install so the gateway stays running.

Setup order

Install Ollama and start it so its local API is available on port 11434. Ollama’s docs state the API becomes available once Ollama is running, and local API access does not require authentication.
ollama
+1

Pull a model in Ollama that you want OpenClaw to use locally, then verify Ollama is responding before touching OpenClaw. The OpenClaw config expects a model provider/model-id string, so you want the local model available first.
ollama.readthedocs
+1

Install OpenClaw with either:

curl -fsSL https://openclaw.ai/install.sh | bash, or

npm install -g openclaw@latest then openclaw onboard --install-daemon.
github
+1

During onboarding, choose the local-model route and point it to Ollama, or set the model afterward in ~/.openclaw/openclaw.json. OpenClaw stores its workspace under ~/.openclaw/workspace by default.
github

Commands to use

A practical local-first sequence looks like this:

bash
# 1) install OpenClaw
npm install -g openclaw@latest

# 2) run onboarding
openclaw onboard --install-daemon

# 3) verify the install
openclaw --version
openclaw doctor
openclaw gateway status

Those commands come directly from OpenClaw’s install and verification docs.
github

For source-based install, OpenClaw documents this flow instead:

bash
git clone https://github.com/openclaw/openclaw.git
cd openclaw
pnpm install
pnpm ui:build
pnpm build
pnpm openclaw onboard --install-daemon

That route is better if you want to inspect or modify the project locally.
github

Config shape

OpenClaw’s minimal config is a JSON file at ~/.openclaw/openclaw.json, and the docs show the model being set with an agent.model field. The exact provider/model naming for Ollama depends on the available local integration in your installed version, so the safest method is to let openclaw onboard generate the correct provider entry rather than hand-writing it first.
github

The minimal pattern is:

json
{
  "agent": {
    "model": "<provider>/<model-id>"
  }
}

That structure is documented by OpenClaw.
github

Recommended local architecture

For a fully local build on your machine:

Ollama runs the model service on localhost:11434.

OpenClaw runs the gateway/assistant as a daemon after openclaw onboard --install-daemon.

Your prompts, skills, and workspace files live under ~/.openclaw/workspace, where OpenClaw also supports custom skills in ~/.openclaw/workspace/skills/<skill>/SKILL.md.

One important security point: OpenClaw states that tools run on the host for the main session by default, so for anything exposed beyond your personal local use, you should review its security and sandbox settings before opening channels or remote access.
github

Best path for you

If your goal is “OpenClaw + Ollama, all local,” use npm install + onboard, not source-build, unless you plan to develop OpenClaw itself. That gives you the fastest route to a working agent while keeping the model local through Ollama.
